# Kezek: режим «Баня и сауна» — ТЗ

Oct 27, 2026 · @Сыймык Рыскулов

Добавляем в Kezek новую сферу **«Баня, сауна, SPA»**: гость платит за вход, получает браслет с номером шкафчика, всё внутри (бар, доп. услуги, услуги мастеров) берёт в долг на этот номер и платит на выходе. Продаём двумя тарифами: «Старт» и «Стандарт».

**Прототип (кликабельный, все экраны):** [Kezek Баня](https://claude.ai/artifact/2rRRmz4QwYTDYPGByT5Vgs). Данные в нём примерные, сервера нет. Всё описанное ниже можно прощёлкать там. Если текст и прототип расходятся, главный — этот документ.

**Основа:** текущий Kezek (front-usluga). Используем существующие модули: сотрудники, касса, смены, склад, онлайн-витрина, филиалы. Новое — шкафчики и браслеты, открытый счёт, бар с остатками, комнаты, зарплата по схемам, тарифы.

**Сквозной сценарий:**

1. Администратор выдаёт браслет: зона, тариф входа, шкафчик. Открывается счёт на номер браслета (= номер шкафчика, например М12).
2. Внутри бармен и мастера вводят номер браслета и записывают покупки и услуги в счёт. Каждая запись сразу приходит администратору.
3. На выходе администратор вводит номер браслета. Если есть долг — система не даёт отпустить гостя без оплаты или явного решения «отпустить с долгом».
4. После оплаты шкафчик освобождается.

## 1. Тарифы и регистрация

Два тарифа, выбираются при регистрации и меняются потом в «Настройки → Тариф».

| Функция | Старт · 2 200 сом/мес | Стандарт · 3 600 сом/мес |
| --- | --- | --- |
| Шкафчики и браслеты по категориям, бронь шкафчиков | ✓ | ✓ |
| Вход, выход, оплата, контроль долга | ✓ | ✓ |
| Касса за день | ✓ | ✓ |
| Сотрудники и доступы | ✓ | ✓ |
| Аналитика по входу и категориям | ✓ | ✓ |
| Каталог: только «Категории и шкафчики» | ✓ | ✓ (все вкладки) |
| Бар: меню, остатки, прибыль | — | ✓ |
| Доп. услуги из продуктов гостя | — | ✓ |
| Услуги мастеров в счёт браслета | — | ✓ |
| Платные комнаты и шахматка | — | ✓ |
| Клиенты и абонементы | — | ✓ |
| Зарплата и авансы | — | ✓ |
| Аналитика бара, услуг, комнат, клиентов | — | ✓ |

**Регистрация (3 шага, как онбординг Kezek):**

1. Название бани и город (название обязательно). Сфера фиксирована: баня, сауна, хаммам, SPA.
2. Выбор тарифа: две карточки с ценой и списком функций (✓ / —). По умолчанию выбран «Стандарт».
3. «Что вы получите»: итог и кнопка «Начать работу». Создаётся компания, владелец входит в систему, заливаются примерные данные (категории М/Ж/VIP, тарифы входа, меню бара), которые можно сбросить.

**Поведение «Старта»:**

- Закрытые разделы (Бар, Услуги в счёт, Комнаты, Клиенты, Зарплата) видны в меню приглушёнными с меткой «Стандарт». При нажатии — страница «Входит в тариф Стандарт» с сравнением тарифов и кнопкой перехода (только у владельца).
- Тарифные ограничения проверяются **на бэкенде**, не только скрытием меню.
- На экранах «Сейчас внутри» и «Вход» скрыты блоки бара, комнат и лента покупок. В аналитике только вход и категории; расходы «Закупка бара» не учитываются.

**Смена тарифа:** через подтверждение на странице. При переходе на «Старт» данные бара, комнат, клиентов и зарплаты **не удаляются**, а скрываются и возвращаются при переходе обратно. Вопрос перерасчёта оплаты при смене тарифа в середине месяца — по правилам биллинга Kezek (в прототипе: «разница добавится к следующему счёту»).

## 2. Роли и права доступа

Каждый сотрудник входит по своему **PIN-коду из 4 цифр** (уникальный в компании). Должность задаёт доступ по умолчанию, владелец может вручную включить или выключить любой раздел и действие для конкретного сотрудника. Смена должности сбрасывает доступ к стандартному для этой должности.

| Должность | Разделы по умолчанию | Действия |
| --- | --- | --- |
| Владелец | Все, доступ не меняется | Все |
| Администратор | Сейчас внутри, Вход, Бар, Услуги, Выход, Комнаты, Касса, Клиенты, Каталог | Долг, лимит, удаление позиций |
| Кассир | Сейчас внутри, Выход и оплата, Касса, Клиенты | — |
| Бармен | Бар | — |
| Банщик, Массажист, Спа-мастер, свои должности | Услуги в счёт | — |

**Разделы (права):** Аналитика, Сейчас внутри, Вход · браслет, Бар, Услуги в счёт, Выход и оплата, Комнаты, Касса за день, Клиенты, Каталог, Сотрудники, Зарплата, Настройки компании.

**Действия (права):** отпускать гостя с долгом; разрешать заказ сверх лимита; удалять позиции из счёта (с записью в историю); добавлять расходы.

- «Настройки → Мой профиль» (имя, телефон, смена PIN, выход, моя зарплата) доступны всем.
- Меню строится из прав: бармен видит только «Бар» и «Настройки». Права проверяются и на бэкенде.
- Отключённый сотрудник не может войти, его история и зарплата сохраняются.
- У владельца есть кнопка «Посмотреть глазами сотрудника» (в прототипе — выход на экран PIN). В рабочей версии можно сделать режим просмотра без ввода PIN.
- В прототипе PIN показан на экране входа для удобства — в рабочей версии **не показывать**; PIN хранить в виде хеша, ограничить число попыток.

## 4. Шкафчики, бронь и выдача браслета

**Статусы шкафчика** (видны везде, где есть сетка):

| Статус | Цвет | Подпись в ячейке | Можно выбрать при выдаче |
| --- | --- | --- | --- |
| Свободен | зелёный | «свободен» | да |
| Занят | голубой; жёлтый, если время по тарифу вышло | текущий долг | нет |
| Бронь | жёлтый с пунктиром | «бронь 20:30» | да, кнопка «Выдать по брони» |
| Ремонт | серый, зачёркнут | «ремонт» | нет |

**Экран «Вход · браслет»:**

1. Зона (категория). При смене зоны подставляется подходящий тариф (VIP → VIP-тариф).
2. Тариф входа с подсказкой: «Включено 3 ч, дальше 100 с за каждый начатый час».
3. Сетка всех шкафчиков зоны со статусами, над ней счётчик «свободно N · занято N · бронь N · ремонт N». По умолчанию выбран первый свободный (не забронированный).
4. Если выбран забронированный — плашка «Шкафчик М20 забронирован: Кубат К., к 20:30» и кнопка «Снять бронь». Выдача браслета снимает бронь (status = used).
5. Если выбран свободный — раскрывающийся блок «Забронировать»: на кого (обязательно) и к какому времени.
6. Клиент (необязательно, поле есть только если включена база клиентов): поиск по имени или телефону. При тарифе «По абонементу» клиент обязателен и должен иметь активный абонемент — списывается 1 посещение.
7. Компания: «пришёл один» / «новая компания» / «присоединить к компании №…». Компания может оплатить одним чеком на выходе.
8. Оплата входа: «в счёт» (по умолчанию) или «оплатить сейчас».
9. Кнопка «Выдать браслет М12» / «Выдать по брони М20» / «Свободных шкафчиков нет» (неактивна).

Справа на экране — блок **«Платные комнаты сейчас»** (только в «Стандарте»), см. раздел 9.

**Экран «Сейчас внутри»:**

- Сверху: гостей внутри, неоплаченные счета (сумма), свободно шкафчиков («ещё N в брони»), превысили время.
- Сетка шкафчиков по всем зонам («занято 7 из 40»). Клик по свободному или брони → экран выдачи с этим шкафчиком. Клик по занятому → окно счёта гостя (позиции, кто и когда добавил, доплата за время, кнопки «В бар», «К оплате», × у позиций при праве удаления).
- Справа: «Гость уходит» (см. раздел 8), «Бар: заканчивается», «Платные комнаты сейчас», «Покупки внутри» (лента).

## 5. Открытый счёт и лента покупок

Каждый выданный браслет = открытый Visit. Все покупки и услуги внутри — VisitItem на этот Visit.

- Начислить можно только на открытый браслет. Неверный номер → «Браслет М99 не выдан». Ввод номера нечувствителен к регистру и пробелам; латинская M трактуется как русская М.
- **Лимит долга** на браслет (настройка, 5 000 с). Заказ сверх лимита без права «разрешать сверх лимита» заблокирован: «Заказ превысит лимит. Позовите администратора». С правом — предупреждение и заказ проходит.
- **Удаление позиции** — только с правом, мягкое (deleted_at, deleted_by), попадает в историю. Позицию «Вход» удалить нельзя.
- **Доплата за время** считается автоматически (формула в разделе 16) и показывается отдельной строкой счёта.

**Лента покупок (администратор видит каждую покупку сразу):**

- Каждая запись бара, доп. услуги или услуги мастера создаёт Notification и **в реальном времени** (WebSocket / SSE) доставляется всем с правом «Сейчас внутри».
- Всплывающее уведомление справа сверху (5 с): «Новая покупка · М11 · Пиво × 2 — 360 с · Талант · долг гостя теперь 1 230 с».
- В верхней панели кнопка «Покупки» со счётчиком непрочитанных → окно со списком (последние 40), открытие отмечает прочитанными (по каждому сотруднику отдельно). Клик по строке → счёт гостя.
- На «Сейчас внутри» — последние 8 покупок, новые подсвечены.

## 6. Бар (Стандарт)

**Экран «Бар → Продажа»** — максимально простой:

- Сверху плашка остатков: «Закончилось: Самса. Заканчивается: Квас — 4 шт…» + кнопка «Пополнить остатки» (если есть право «Каталог»).
- Плитки по категориям: название, цена, «ост. N» (оранжевым, если ≤ порога). Остаток 0 → плитка серая «нет в наличии», неактивна.
- Отдельный блок «Доп. услуги · из продуктов гостя» (пунктирные плитки) + плитка **«+ Новая доп. услуга»**: бармен сам вводит название, цену и примерную себестоимость → услуга сохраняется в каталог и сразу кладётся в заказ. Дубли по названию запрещены.
- Справа: номер браслета (или занятая сейчас комната), карточка гостя с долгом и шкалой лимита, заказ (− убирает 1 шт), кнопка «В счёт М12».
- Нельзя положить в заказ больше, чем остаток: «Пиво: осталось только 3 шт». Списание остатка — атомарно на бэкенде (два бармена не должны продать последнюю бутылку дважды).
- После продажи: если остаток стал ≤ порога — уведомление «Заканчивается в баре: Квас — осталось 4 шт» (оранжевое); если 0 — «Закончилось» (красное). Приходит бармену, администратору и владельцу.
- Можно записать на комнату: позиции идут в счёт брони комнаты.

**Экран «Бар → Меню бара»** (право «Каталог»; то же в «Каталог → Меню бара»):

- Категории (переименовать, добавить, удалить только пустую).
- В каждой — таблица с правкой прямо в ячейках: **название · закупка / себестоимость · цена продажи · остаток, шт · прибыль с 1 шт (сом и %)**. Прибыль пересчитывается сразу. Пустой остаток = не считаем (чай, кальян, прокат).
- Поле «Предупреждать, когда остаётся N шт или меньше».
- Ниже — таблица доп. услуг (название · себестоимость · цена · прибыль).
- Интеграция остатков с существующим «Складом» Kezek — на усмотрение разработчика; если склад уже ведёт остатки, использовать его.

## 7. Услуги мастеров в счёт (Стандарт)

Мастер сам отмечает оказанную услугу, чтобы она ушла в долг гостя, а ему начислился процент.

1. Номер браслета гостя → карточка гостя с долгом.
2. Услуга (плитки: название, цена, кто делает).
3. «Кто сделал — выберите себя»: список мастеров **на смене** (см. раздел «Смены»). Если вошёл мастер — он выбран сразу.
4. Справа «Проверьте»: браслет, услуга, цена, мастер и «Мастеру начислится 600 с (30%)». Кнопка «Записать услугу в счёт М22».
5. Ниже — услуги мастера за сегодня и сколько он заработал.

Услуга создаёт VisitItem (source = service, employee_id = мастер) и уведомление администратору. В дальнейшем в существующем журнале записи Kezek можно выбирать клиентом «Браслет №…», чтобы после выполнения услуга уходила в счёт автоматически.

## 8. Выход, оплата и контроль долга

**«Гость уходит»** (на экране «Сейчас внутри»): администратор вводит или сканирует номер браслета.

- Долг > 0 → красное окно **«Не отпускайте без оплаты! Долг гостя: N с»** с разбивкой: вход и время, бар, доп. услуги, услуги. Если у клиента есть **старый долг с прошлых визитов** — отдельной красной строкой. Если гость в компании — общий долг компании. Кнопка «Перейти к оплате».
- Долга нет → зелёное «Счёт оплачен, можно отпускать» + «Освободить шкафчик».
- Браслет не выдан → «не выдан или уже оплачен — можно отпускать».

**Экран «Выход и оплата»:**

- Слева: поиск по номеру или список «Ждут оплаты»; после выбора — полный чек (позиция, откуда, кто, сумма) и доплата за время.
- Справа: красная плашка «Внимание: долг N с. Браслет не освободится без оплаты»; чекбокс «Взять старый долг клиента N с»; переключатель «Только М3 / За всю компанию»; итог по источникам (вход и время, бар, доп. услуги, услуги, старый долг); способ оплаты (только включённые в настройках).
- «Принять N с и освободить М3, М4» → Payment, Visit.status = paid, шкафчики свободны, старый долг обнулён (если отмечен).
- «Отпустить с долгом на карточку клиента» — только с правом. Visit.status = debt, сумма добавляется к Client.debt, шкафчик освобождается. Кнопку стоит показывать, только если в счёте есть клиент (иначе долг не на ком висит) — в прототипе это не проверяется.

**Касса за день:** принято, закрыто счетов, ещё не оплачено, средний чек; таблица счетов (время, браслет / комната / абонемент, способ, сумма, метка «долг»); итоги по способам оплаты. В рабочей версии — в разрезе кассовой смены (см. «Смены»).

## 9. Платные комнаты (Стандарт)

- Карточки комнат: название, вместимость, цена за час, минимум часов и **статус**:

| Статус | Условие | Подпись |
| --- | --- | --- |
| занята | идёт активная бронь | «до 21:00 · Кубат К., 6 гостей» |
| уборка | 30 минут после закрытия брони | «будет готова к 21:30» |
| бронь с HH:MM | свободна, но сегодня есть будущая бронь | «свободна до 20:00 · Мирлан Т.» |
| свободна | броней больше нет | «сегодня броней больше нет» |

- Действия: «Заселить сейчас на N ч» (если до следующей брони хватает минимального времени, иначе ошибка), «+1 час» (продление с доплатой, проверять пересечение со следующей бронью — в прототипе не проверяется), «В бар» (заказ на комнату), «Закрыть и оплатить» (сумма счёта комнаты минус предоплата).
- Шахматка на день: комнаты × часы с 10:00 до 02:00, текущая бронь выделена. Ночные брони переходят через полночь. В рабочей версии нужно создание будущей брони кликом по свободной ячейке (в прототипе нет) и предоплата при онлайн-брони через витрину.
- Блок «Платные комнаты сейчас» с теми же статусами — на экранах «Вход» и «Сейчас внутри».

## 10. Клиенты и абонементы (Стандарт, необязательный модуль)

Многие бани не записывают имена, поэтому база клиентов включается галочкой «Вести базу клиентов» (Настройки → Зал и тарифы). Выключена → нет раздела «Клиенты», поля клиента при входе, тарифа «По абонементу», вкладки «Абонементы» и блока клиентов в аналитике.

- Список: поиск по имени или телефону, визитов, потратил, абонемент («4 из 10»), когда был, долг.
- Новый клиент: имя или телефон (хотя бы одно), телефон уникален.
- Карточка: визитов, потратил, средний чек, «обычно берёт»; долг с прошлых визитов + «Погасить»; абонементы (осталось N из M, действует до); «Продать абонемент» (выбор из каталога + способ оплаты → Payment в кассу); история посещений (дата, зона, сумма, «сейчас внутри»).
- Вход по абонементу списывает 1 посещение; нет активного → ошибка. Просроченный по сроку абонемент считается неактивным (в прототипе срок не проверяется).
- Данные клиентов — персональные: доступ только по праву «Клиенты».

## 12. Сотрудники и зарплата

**Сотрудники:** таблица (имя, телефон, должность, схема оплаты, доступ, статус). Добавление: имя (обяз.), телефон, должность, PIN (4 цифры, уникальный), схема оплаты. Карточка: схема оплаты, должность, галочки разделов и действий, отключить / включить.

**Схема оплаты** — 5 частей, заполняются нужные и складываются: оклад в месяц; ставка за смену; % от своих услуг; % от своих продаж в баре; фикс за каждую услугу. Процент ≤ 100. Шаблоны-кнопки: «Оклад», «Процент», «Оклад + процент», «Смена + процент», «Только смены», «За каждую услугу».

**Раздел «Зарплата»** (по умолчанию только владелец), период — месяц:

- Карточки: начислено, выдано авансов («долг сотрудников до зарплаты»), осталось выплатить, ФОТ в % от выручки.
- Таблица: сотрудник, как получает, начислено, аванс, к выплате (или «долг N», «выплачено»).
- Детали сотрудника: разбивка по частям схемы, список авансов, уже выплачено, итог; «Выдать аванс» (сумма + комментарий); «Выплатить N с»; записи за сегодня.
- Аванс больше заработанного → предупреждение; отрицательный остаток переносится в следующий месяц как долг сотрудника.
- Аванс и выплата автоматически создают расход «Зарплата».
- Вопрос: считать процент мастера с момента записи услуги или только после оплаты счёта гостем? Предлагаю: показывать сразу, но учитывать в выплате только оплаченные и долговые (не удалённые) позиции.

**Моя зарплата:** в «Настройки → Мой профиль» каждый сотрудник видит свои начисления, авансы и «Получу / Мой долг».

## 13. Смены

Бани работают допоздна и круглосуточно, сотрудники выходят по сменам. Смены нужны для трёх вещей: кто сейчас работает, сколько смен оплатить, и кто отвечает за деньги в кассе. В прототипе смены заданы вручную (число смен в месяце), в рабочей версии — как описано ниже. Использовать существующий раздел «Смены» Kezek, доработав его.

**13.1. Шаблоны смен** (Настройки): название, начало, конец (может быть после полуночи). Примеры: «Дневная 10:00–20:00», «Ночная 20:00–04:00», «Сутки 10:00–10:00».

**13.2. График** (владелец и администратор):

- Таблица «сотрудники × дни недели / месяца», в ячейке — шаблон смены или «выходной».
- Быстрое заполнение: «2 через 2», «сутки через трое», «5/2», копировать неделю.
- Предупреждение, если на какую-то смену нет ни одного администратора.
- Сотрудник видит свой график в «Мой профиль».

**13.3. Открытие и закрытие смены сотрудником:**

- При входе по PIN, если у сотрудника по графику есть смена, — кнопка «Начать смену» (фиксируется фактическое время). Опционально — селфи при отметке (можно переиспользовать наработки приложения учёта прихода сотрудников).
- Опоздание больше N минут (настройка, например 15) — отметка «опоздал на N мин» и уведомление владельцу. Смена не начата через N минут после начала — тоже уведомление.
- «Закончить смену» — в меню профиля. Забыл закрыть — администратор или владелец закрывает вручную с указанием времени.
- Работа вне смены не запрещена, но помечается (например, владелец входит проверить).

**13.4. Кто на смене — влияет на экраны:**

- В «Услуги в счёт» в списке «Кто сделал» — только мастера на открытой смене (ссылка «показать всех» — для исключений).
- В «Сейчас внутри» — блок «На смене»: список сотрудников с должностями и временем начала.
- **Исправить баг Kezek:** в текущем «Потоке» сотрудники с выходным показаны как «Свободен» и могут получить клиента из очереди. Должны быть скрыты или помечены «Выходной».

**13.5. Кассовая смена** (администратор / кассир):

1. Открытие: начальный остаток наличных (подставляется остаток прошлой смены). Без открытой кассовой смены нельзя принимать оплату.
2. Все Payment привязываются к текущей кассовой смене. Выдача аванса наличными и расходы из кассы уменьшают ожидаемый остаток.
3. Закрытие: система показывает ожидаемые наличные, администратор вводит факт. Расхождение сохраняется и видно владельцу (уведомление при недостаче).
4. Отчёт смены: выручка по способам оплаты и источникам (вход, бар, доп. услуги, услуги, комнаты), гостей, отпущено с долгом, удалённые позиции, авансы.
5. **Открытые браслеты при закрытии смены:** предупреждение «Внутри N гостей с неоплаченными счетами на сумму X»; счета переходят в следующую смену и видны ей. Оплата засчитывается в ту смену, где приняты деньги.
6. Ночная смена через полночь относится к дате начала.

**13.6. Связь с зарплатой и аналитикой:**

- «Ставка за смену» считается по **закрытым фактическим сменам**. Владелец может поправить число вручную («+1 / −1 смена» в Зарплате, с записью в историю).
- Добавить в схему оплаты вариант **«за час»** (часы из фактических смен) — для смен разной длины.
- Аналитика: выручка по сменам и по администраторам, расхождения в кассе, опоздания.
- В тарифе «Старт»: график и кассовая смена доступны (нужны для контроля кассы), расчёт зарплаты — нет.

Период: сегодня / неделя / месяц (переключатель как в Kezek). Все цифры — из реальных чеков (Payment, VisitItem, Expense). В прототипе данные сгенерированы.

| Блок | Что показывает | Тариф |
| --- | --- | --- |

| Выручка по дням | столбцы по источникам: вход, бар, доп. услуги, услуги, аренда комнат (14 или 30 дней) | оба (в Старте только вход) |

## 16. Формулы расчётов

| Что | Формула | Пример |
| --- | --- | --- |
| Доплата за время | если included_hours > 0: перебор = минуты внутри − included_hours × 60; если перебор > 0 → ⌈перебор / 60⌉ × extra_per_hour | 3 ч + 100 с/ч, внутри 3 ч 35 мин → 100 с |
| Долг гостя | Σ (price × qty) не удалённых VisitItem + доплата за время | — |
| К оплате на выходе | долг гостя (или всех браслетов компании) + старый долг клиента, если отмечен | 1 230 + 6 400 = 7 630 с |
| Проверка лимита | долг + сумма заказа > debt_limit → нужен право «лимит» | 4 800 + 900 > 5 000 |
| Прибыль с позиции | price − cost; маржа = (price − cost) / price | Пиво 180 − 95 = 85 с, 47% |
| Статус остатка | stock = null → не считаем; 0 → «нет в наличии»; ≤ low_stock_threshold → «заканчивается» | порог 5, остаток 4 → заканчивается |
| Зарплата за месяц | salary + смен × per_shift + свои услуги × pct_services / 100 + свои продажи бара и доп. услуг × pct_bar / 100 + число услуг × per_service | 15 000 + 277 800 × 30% = 98 340 с |
| К выплате | начислено − авансы − уже выплачено; < 0 → долг сотрудника | 98 340 − 11 000 = 87 340 с |
| Начисление мастеру за услугу | price × pct_services / 100 + per_service | 2 000 × 30% = 600 с |
| ФОТ | Σ начислено / выручка месяца | — |
| Загрузка категории | гостей в день / (шкафчиков × 3 смены гостей в день); коэффициент 3 — предложение, уточнить | — |
| Комната к оплате | аренда (часы × price_per_hour, не меньше min_hours) + продления + бар на комнату − предоплата | — |
