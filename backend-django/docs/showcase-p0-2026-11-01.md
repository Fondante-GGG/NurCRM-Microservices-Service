# Витрина P0 — что изменилось (01.11.2026)

Для разработчика кассы / программы владельца и для фронта витрины. База адресов: `https://app.nurcrm.kg/api/main/`.
Признаки в `GET /api/main/capabilities/` → `features`: `showcase_telegram`, `showcase_cart_link`, `showcase_order_source_detail`.

## 1. Блок `telegram` в публичном дизайне

`GET public/companies/{slug}/showcase/design/` теперь содержит ключ `telegram`:

```json
"telegram": {
  "enabled": true,
  "url": "https://t.me/nbs_shop_bot",
  "product_url_template": "https://t.me/nbs_shop_bot?start=p_{id}",
  "placement": ["cart", "product"],
  "label": {"ru": "Заказать в Telegram"}
}
```

`enabled = true` только если одновременно: бот компании в режиме «сервер» (`mode=server`), webhook установлен
и владелец включил `cart.telegram.enabled` в дизайне. Иначе `enabled=false`, `url` и `product_url_template` равны `null`.
Токена бота здесь нет и не будет. Бот в режиме «касса» (`local`) всегда даёт `enabled=false`.
Публичный ответ кэшируется по состоянию бота: включили/выключили бота — витрина обновится сама.

Ссылку на товар получить так: заменить `{id}` в `product_url_template` на id товара.

Настройки владельца (редактор): `PATCH showcase/design/draft/` и публикация как обычно:

```json
{"cart": {"telegram": {"enabled": true, "placement": ["cart", "product", "header", "floating"],
                       "label": {"ru": "Заказать в Telegram", "ky": "Telegram аркылуу буйрутма"}}}}
```

- `enabled` — bool (по умолчанию `false`).
- `placement` — список из `cart`, `product`, `header`, `floating` (без повторов).
- `label` — текст по языкам `ru, ky, en, uz, kk`, до 40 символов.

## 2. Заказ: `source`, `source_detail`, `cart_token`

`POST public/companies/{slug}/orders/` — новые необязательные поля:

```json
{
  "customer": {"name": "Айбек", "phone": "+996555123456"},
  "items": [{"product": "<uuid>", "variant": null, "qty": "2"}],
  "source": "web_chat",
  "source_detail": "assistant",
  "cart_token": "Xk3_..."
}
```

- `source`: `showcase` (по умолчанию), `telegram_bot`, `voice_ai`, `whatsapp`, **`web_chat`** (новое).
- `source_detail`: свободная метка `[A-Za-z0-9_.-]`, до 32 символов, можно пусто. Договорные значения:
  `site_cart`, `assistant`, `product_card`, `bot_catalog`.
- `cart_token`: токен из `cart-link/` (см. п. 3). Один токен — один заказ. Повтор с тем же токеном
  возвращает тот же заказ с кодом `200` и `"replayed": true`. Неизвестный токен → `400`, `code: cart_link_not_found`.
  Если `source_detail` не передан, а токен есть — ставится `site_cart`.
- Ответ создания теперь содержит `source_detail`. Повтор по `Idempotency-Key` работает как раньше (`200`, `replayed`).
- Заказы, оформленные в боте из обычного каталога, получают `source=telegram`, `source_detail=bot_catalog`.

Список для кассы/владельца: `GET showcase/orders/?source=web_chat&source_detail=assistant`
(фильтры по отдельности и вместе). В каждой строке (и в карточке заказа) появились `source_detail` и `cart_token`
(`cart_token` только для чтения, может быть `null`).

## 3. Корзина сайта → Telegram

`POST public/companies/{slug}/cart-link/` (без авторизации):

```json
{"items": [{"product": "<uuid>", "variant": "<uuid или null>", "qty": "2"}]}
```

Ответ `201`:

```json
{"token": "k3J9x0bq2-aZ_4Qh7wLmNg", "expires_at": "2026-11-08T12:00:00+00:00"}
```

- Токен — URL-безопасный, `[A-Za-z0-9_-]`, 22 символа. Ссылка для клиента: `https://t.me/<bot>?start=c_<token>` (`c_` + токен ≤ 64).
- Цены в токен **не** сохраняются: бот берёт названия, варианты и цены из базы в момент открытия.
- Срок жизни — 7 дней. До 50 позиций. Лимит — 20 ссылок в час с одного IP (`429`, `code: throttled`).
- Ошибки: `400 product_not_found` (товара нет или он скрыт с витрины), `400 variant_not_found`.
- Каждая созданная ссылка сама увеличивает счётчик `cart_link` в статистике — фронту отдельное событие `cart_link` слать не нужно.

Бот (режим «сервер»):

- `/start c_<token>` — показывает состав корзины (название, вариант, количество, сумма) и кнопки
  «Самовывоз / Доставка / Подтвердить / Отменить» (общий поток оформления бота). Заказ создаётся с
  `source=telegram_bot`, `source_detail=site_cart`, `cart_token=<token>`.
  Повторное открытие ссылки или двойное нажатие «Подтвердить» — «Этот заказ уже оформлен: №N», нового заказа нет.
  Ссылка устарела / не найдена — сообщение «Ссылка на корзину устарела».
- `/start p_<id>` — карточка товара с кнопками количества / «В корзину» / «Оформить» (с выбором размера, если есть варианты).
- `/start w_<token>` (чат на сайте) и `/start <client_id>` работают как раньше.

## 4. События статистики

`POST public/companies/{slug}/showcase/events/` `{"type": "...", "session": "..."}` — допустимые типы теперь:
`view`, `product_view`, `banner_click`, `add_to_cart`, **`assistant_open`**, **`assistant_message`**,
**`telegram_click`**, **`cart_link`** (последние четыре — без `id`). Старый адрес `showcase/track/` принимает те же значения в поле `event`.

`GET showcase/stats/` (владелец) возвращает суммы за период в полях `assistant_open`, `assistant_message`,
`telegram_click`, `cart_link` рядом с `views` и `add_to_cart`.

## 5. Знания о магазине для ИИ (`shop.info.knowledge`)

Ключ дизайна: `{"shop": {"info": {"knowledge": {"ru": "...", "ky": "..."}}}}`.
Сохраняется через `PATCH showcase/design/draft/` и публикуется как остальные настройки. Языки `ru, ky, en, uz, kk`,
до 2000 символов на язык (длиннее — `400`). **В публичный дизайн не попадает** (раздел закрытый).
Для сервера: `apps.main.showcase.services.get_shop_knowledge(company, lang="ru") -> str` — опубликованный текст,
нет нужного языка — берётся `ru`, пусто — `""`.

## 6. Мелочи для кассы

- `SaleItem.line_total` и `cart_service._money` теперь округляют «0.005 → 0.01» (ROUND_HALF_UP), а не банковским способом, как `_money` в `models.py`. Логика `Cart.recalc` не менялась.
- `POST branch-transfers/` принимает ключ повтора и в заголовке `Idempotency-Key`, и в теле `idempotency_key`. Повтор с тем же ключом возвращает то же перемещение (остатки списываются один раз).
- Возврат долговой продажи: в `debt_adjustment` поле `remaining_debt` теперь равно `remaining_debt_before − reduced_by` (раньше после полного возврата могло показывать завышенный остаток). Пример: долг 3.00, оплачено 2.00, остаток 1.00, полный возврат 3.00 → `remaining_debt_before: "1.00"`, `reduced_by: "1.00"`, `remaining_debt: "0.00"`, `cash_refund_due: "2.00"`, `deal_status: "canceled"`.
