## Ответы владельца (12.10.2026) и решение

- **В1–В3.** Бэк не готов. Значит, каркас к презентации работает на примерных данных внутри фронта; заливаем фронт на Vercel (бесплатно, ссылка для показа) и держим локальный запуск как запасной вариант. Стейдж бэка — после презентации.
- **В4.** Вход не показываем: `AUTH_ENABLED = false`, сайт открывается сразу в «Услуги».
- **В5.** Филиалы нужны, чтобы владелец из своего аккаунта смотрел другие точки: переключатель филиала в шапке с пунктом «Все филиалы» делаем сразу.
- **В24.** Компоненты схемы зарплаты, которые нужны:
  1. ставка за услугу — % или фиксированная сумма с конкретной услуги;
  2. за запись — фикс или % с каждой записи (для администратора, который её оформил);
  3. фиксированная сумма за месяц — оклад;
  4. процент от своей выручки с условием по дню: выполнил за день N записей → получает X % от выручки дня;
  5. для администратора — % от выручки филиала за месяц (например 10–15 %, если филиал закрыл месяц на 100 000 с), с порогом.
- **В27.** Рекомендация: окончательный расчёт — на бэке Беки (один источник для сайта, кассы и приложения). Но правила расчёта пишем сейчас как отдельный модуль на TypeScript без привязки к экрану (`src/lib/payroll/`), с примерами-проверками. На презентации он считает на примерных данных, а потом этот же модуль с примерами уходит Беке как ТЗ: правила совпадут один в один, споров «фронт посчитал иначе» не будет.
- **В31.** Презентация в понедельник 19.10.2026.

## 0. Стейдж: где живёт и как заливаем

- Фронт: Next.js собирается в Node-сервер (`npm run build && npm start`) или в Docker. Нужен сервер с Node 20+ или аккаунт Vercel. Переменные: `NURCRM_API_URL` (адрес стейдж-бэка), `AUTH_ENABLED`.
- Бэк: Бека поднимает стейдж-копию NurCRM (отдельная база, тестовая компания «Услуги»).
- Домены: например `stage.nurcrm.kg` (фронт) и `stage-api.nurcrm.kg` (бэк); фронт ходит на бэк только через свои route handlers, поэтому CORS не нужен.
- Вход на стейдже включаем (`AUTH_ENABLED = true`), чтобы показать общую страницу входа и переход в «Услуги» по ответу сервера.

### 2.14 Зарплата (главный экран презентации)
Подразделы (вкладки сверху):
1. **Схемы** — список схем по должности. Конструктор схемы: компоненты списком, каждый — карточка с настройками:
   - % от услуг (ставка по умолчанию; переопределения по категории/услуге; роли: один / с помощником / помощник);
   - фикс за услугу; % от товаров (от оплаты или от маржи);
   - за смену / за час (по факту смен); оклад в месяц; гарантированный минимум за день/месяц;
   - **ступени**: метрика (оборот/прибыль/количество), период (неделя/полмесяца/месяц), тип **прогрессивная** (каждая часть по своей ставке) или **ретроактивная** (достиг порога — вся сумма по новой ставке), пороги и ставки таблицей;
   - бонус KPI (повторные клиенты %, средний чек, новый клиент +N);
   - аренда места (минус за период), вычеты (с типом и причиной).
   - База расчёта: скидка клиента (за счёт салона → не вычитать / за счёт мастера → вычитать), бонусы, абонементы, материалы по техкарте (полностью / пропорционально / нет), эквайринг (нет / доля).
   - Версии: «действует с …»; старые визиты считаются по старой версии.
   - Справа — живой пример: «Стрижка 1 500 с, скидка 10 %, материалы 50 с → мастеру 580 с».
2. **Период** (день / период): таблица мастеров: начислено по источникам (услуги, товары, смены, бонусы, вычеты), итого, выплачено, к выплате. Клик → начисления мастера построчно, у каждой строки «объяснение»: «Стрижка 1 500 → скидка −150 (за счёт мастера) → материалы −50 → база 1 300 × 40 % = 520».
3. **Ведомость**: по периоду и филиалу; статусы черновик → проверка → ознакомление мастера → утверждена → выплачена. Кнопки по статусу. Возражения мастера по строкам с комментарием, ответ владельца.
4. **Выплаты**: выплата из кассы (частями), аванс, баланс взаиморасчётов по мастеру.
5. **Симулятор**: выбрать схему-кандидата, период из прошлого (1–6 мес.), мастеров → таблица «было / стало / разница» по каждому и итог по ФОТ.
6. **Кабинет мастера** (видит мастер под своим логином): «Сегодня заработано», лента начислений с объяснением, прогресс к ступени (полоса), прогноз до конца месяца, мои ведомости, кнопка «Оспорить».
- Данные: `GET/POST /payroll/schemes`, `GET /payroll/accruals?period&staff`, `GET/PATCH /payroll/payslips`, `POST /payroll/payouts`, `POST /payroll/simulate`.

**В24.** На презентации какую схему показываем как пример? (Предположение: барбер — 40 % от услуг, ретроактивная ступень 50 % при обороте от 150 000 с/мес, минимум 1 000 с за смену; администратор — оклад + 2 % от дневной выручки.)
**В25.** Аванс нужен первому клиенту? (Предположение: да, выплата частями без лимита.)
**В26.** Ведомость подписывает мастер (кнопка «Ознакомлен») — делаем в каркасе? (Предположение: да, это главная «фишка».)
