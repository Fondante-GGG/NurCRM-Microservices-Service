## 2. Зарплата: что строим (экраны)

1. **Схемы оплаты** — по должности, с исключениями на сотрудника. Компоненты: % от услуг (своя ставка на услугу/категорию), фикс за услугу, % от товаров, за смену/час, оклад, гарантированный минимум, ступени (прогрессивные и ретроактивные — на выбор), бонусы KPI, аренда места, вычеты. База расчёта настраивается: скидки, бонусы, материалы, эквайринг.
2. **Периоды** — день/неделя/полмесяца/месяц; открыт → заблокирован → закрыт. Правка в закрытом периоде создаёт корректирующую строку в открытом, возврат чека — автоматическое сторно.
3. **Начисления** — каждая строка от события (визит закрыт, продажа, смена, возврат) с объяснением словами: «Маникюр 2000 → скидка −200 (за счёт салона, не вычитаем) → материалы −150 → база 1850 × 40 % = 740».
4. **Ведомость** — черновик → проверка → ознакомление мастера → утверждение → выплата (частями, из разных касс). Мастер может оспорить строку с комментарием.
5. **Кабинет мастера** — «заработано сегодня», расшифровка каждого чека, прогресс к ступени, прогноз на конец месяца.
6. **Симулятор «что если»** — прогнать новую схему на 3–6 месяцев факта: до/после по каждому мастеру и влияние на ФОТ. Калькулятор для оффера.
7. **Документы и налоги** — профиль по стране (первые: KG, KZ), расчётный лист, акт для самозанятого, экспорт в банк/CSV.

Полный список требований (56 пунктов) и 24 краевых случая: `~/altegio-research/research/05-payroll-practices.md`, разделы 5–6. Модель данных для бэкенда: `00-ИТОГ…`, раздел 5.

## 3. Аналитика: что строим

- Дашборд владельца: выручка, записи, загрузка, средний чек, возвращаемость, новые/постоянные, источники записи — по дню/неделе/месяцу, по филиалам.
- ФОТ: доля от выручки по филиалу и периоду, порог (например 45 %) с предупреждением.
- Мастера: выручка, эффективная ставка, рентабельность после материалов и аренды, заполненность, повторные записи, средний чек.
- Услуги и товары: что продаётся, маржа, комиссия по типам.
- Прогноз: выручка и ФОТ до конца периода по уже стоящим записям.

## 4. Порядок работы над сайтом

Бэкенда под это ещё нет: Бека делает API по нашему ТЗ. Чтобы не ждать, экраны собираем сначала на локальных примерных данных (в коде помечены как примерные), потом подключаем запросы.

1. **Сотрудники + Услуги + Смены** — справочники, без них нечего считать.
2. **Записи + Продажа** — журнал и закрытие визита: отсюда рождаются начисления.
3. **Зарплата** — схемы, начисления с объяснением, ведомость, кабинет мастера.
4. **Аналитика** — дашборд, ФОТ, мастера.
5. Остальное: Клиенты, Документы, Заявки, Касса, Склад, История, Филиалы, Настройки.

Для Беки отдельно: ТЗ на зарплатный движок (разделы 5–6 итога исследования) — событийные начисления, версии схем, закрытие периодов, ведомости, API на запись.
