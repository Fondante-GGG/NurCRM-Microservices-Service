# ТЗ для Беки: сферы, режим приёма, техподдержка и панель поддержки (стейдж)

Умар, 15.10.2026. Для сайта «Услуги» (репозиторий front-usluga). Всё описанное уже работает во фронте на примерных данных; нужны эти запросы на стейдже, чтобы заменить примерные данные настоящими. Названия полей — как ниже, фронт под них написан.

## 1. Сфера компании и режим приёма

У компании появляются два поля:

- `industry`: `barber` | `beauty` | `procedure` | `massage`. Пусто у нового аккаунта.
- `intake`: `schedule` (по записи) | `flow` (поток без записи). `flow` разрешён только при `industry = procedure`; при другой сфере сервер отвечает 400.

Запросы:

- `GET /api/main/company/` — отдаёт `industry`, `intake`, `name`, `legal_name`, `inn`, `okpo`, `account`, `bik`, `address`, `phones`.
- `PATCH /api/main/company/` — владелец может менять `intake` и реквизиты. **`industry` владелец менять не может** (403); его ставит сервер при первом выборе и дальше только поддержка.
- `POST /api/main/company/industry/` с телом `{"industry": "procedure"}` — первый выбор сферы при пустом значении. Повторный вызов — 409. По сфере сервер создаёт стартовые должности и категории услуг (список — в `src/lib/industry.ts`, файл `PROFILES`).

Что значит «поток» для записей: запись без времени слота. В `POST /api/main/appointments/` при `intake = flow` поле `start` = момент добавления в очередь, `duration` берётся из услуг, статусы те же: `pending` (в очереди) → `arrived` (принимают) → `paid` (принят, визит закрыт). `staff` может быть пустым (любой свободный); при переводе в `arrived` фронт присылает `staff`.

Флаг «Занят» у специалиста на день: `PATCH /api/main/shifts/{id}/` с `fact: "busy"` (новое значение рядом с `planned | worked | missed`). Занятый не предлагается очередью.

## 2. Обращения в техподдержку (со стороны клиента)

- `GET /api/main/support/tickets/` — обращения своей компании.
- `POST /api/main/support/tickets/`:
  ```json
  {"topic": "industry|setup|bug|other", "message": "…", "contact": "+996…", "share_access": true}
  ```
  Ответ: обращение со статусом `new`. Если `share_access = true`, сервер сам выдаёт поддержке временный доступ на 72 часа (п. 4) — паролей клиент не вводит.
- Поля обращения: `id, created_at, topic, message, contact, share_access, status (new|in_progress|done), assignee (имя сотрудника поддержки), reply`.
- `GET /api/main/company/temp-access/` — `{"until": "2026-10-18T19:40+06:00" | null}`.
- `DELETE /api/main/company/temp-access/` — владелец отзывает доступ.

## 3. Панель поддержки (роль `support`)

Отдельная роль пользователя NurCRM `support` (сотрудники NurCRM). Все запросы под `/api/support/…`, для остальных ролей 403.

- `GET /api/support/companies/?q=` — поиск по названию, телефону, ИНН. Поля: `id, name, phone, inn, industry, intake, branches_count, staff_count, plan (free|trial|paid), last_login, blocked, temp_access_until`.
- `GET /api/support/companies/{id}/` — карточка + список филиалов `[{id, name, address}]`.
- `PATCH /api/support/companies/{id}/` — `industry`, `intake`, `blocked`. Смена `industry` пересоздаёт стартовые должности и категории, но **не трогает** записи, клиентов, чеки и сотрудников (сотрудники получают должность «Специалист» по новой сфере).
- `POST /api/support/companies/{id}/branches/` `{name, address}` и `DELETE /api/support/companies/{id}/branches/{bid}/` — подключение и отключение филиалов. **Владелец филиалы создавать не может** (во фронте кнопка ведёт в поддержку); `POST /api/main/branches/` от владельца → 403.
- `POST /api/support/companies/{id}/temp-access/` → `{until}` (72 часа); `DELETE …/temp-access/` — отозвать.
- `POST /api/support/companies/{id}/reset-password/` — отправить владельцу ссылку на новый пароль.
- `GET /api/support/tickets/?status=` — все обращения; `PATCH /api/support/tickets/{id}/` — `status`, `assignee`, `reply`. При `status = done` сервер отзывает временный доступ, если обращение было с `share_access`.
- `GET /api/support/log/?company=` — журнал (п. 5).

## 4. «Войти как владелец» (impersonation)

- `POST /api/support/companies/{id}/impersonate/` — только если `temp_access_until` в будущем, иначе 403. Ответ: короткоживущий токен (1 час) с правами владельца этой компании и признаком `impersonated_by = <support user>`.
- Все запросы с таким токеном работают как от владельца, но сервер пишет каждое изменение в журнал (п. 5) и в историю компании (`/api/main/audit/`) с автором «Техподдержка: Имя».
- `POST /api/support/impersonate/exit/` — завершить сессию (фронт зовёт при выходе из аккаунта клиента).
- Фронт показывает оранжевую полосу «Вы в аккаунте … как поддержка» и кнопку выхода; ему нужно знать `impersonated_by` в ответе `GET /me`.

## 5. Журнал действий поддержки

Таблица `support_log`: `id, at, agent (имя), company, action (текст)`. Пишется сервером при: смене сферы и режима, подключении/отключении филиала, выдаче/отзыве доступа, входе и выходе из аккаунта клиента, блокировке, сбросе пароля, закрытии обращения, и при любом изменении данных компании под impersonation-токеном. Записи по компании должны быть видны и клиенту в `GET /api/main/audit/` (фронт показывает их в разделе «История» с автором «Техподдержка»).
